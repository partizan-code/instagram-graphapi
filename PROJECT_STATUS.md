# Состояние проекта

Обновлено: 22 ноября 2026.

## Текущее состояние

Чтение Direct через Meta Unified Login и отдельный диагностический FastAPI/Uvicorn
webhook-сервер. Чтение — `mise run start`, сервер — `mise run webhook`, без аргументов
приложения. Ветка `main` отслеживает `origin/main`; fetch перед задачей подтвердил
отсутствие расхождений. Коммиты и push в этой задаче не выполнялись.

## Webhook-сервер через tuna

- `webhook_server.py` запрашивает публичный HTTPS-адрес туннеля в консоли и
  выводит Callback URL с `/webhook`. Слушает только `127.0.0.1:8000`.
- `GET /webhook` проверяет verify token и возвращает challenge; `POST /webhook`
  проверяет HMAC-SHA256 исходного тела с Meta APP_SECRET и структуру события
  instagram. `GET /health` возвращает только состояние сервера.
- Лимит тела — 1 МиБ, чтения — 10 секунд. В общий Loguru выводятся результаты и
  количества событий; тексты, ID, секреты и сырые ошибки не передаются. HTTP access/
  error-журналы Uvicorn отключены централизованно.
- `mise run tunnel` выполняет `tuna http 8000 --inspect=false`. Добавлены FastAPI,
  Uvicorn и dev-зависимость httpx, обновлён uv.lock. Пакеты установлены через uv
  в существующее внешнее окружение. Настройка описана в `docs/WEBHOOKS.md`.
- WEBHOOK_VERIFY_TOKEN добавлен в `.env.example`; настоящий `.env` не менялся.
- Итог: 92 passed, включая 42 новые проверки, Ruff lint и format --check успешны.
  Webhook-тесты используют httpx ASGITransport и фиктивные ключи. Блокировки сети
  и загрузки .env сохранены. На Windows служебная пара сокетов asyncio создаётся
  перед включением блокировок; TestClient заменён из-за этой несовместимости.
  Для pytest использована уникальная временная папка в игнорируемом `.cache/`.
- Реальная доставка tuna/Meta ещё не проверялась, сервер и туннель не оставлены
  запущенными. Следующий шаг: заполнить WEBHOOK_VERIFY_TOKEN, проверить APP_SECRET,
  запустить обе задачи, подтвердить callback и нажать Dashboard Test в Meta.
  Для реального Direct дополнительно нужны подписка аккаунта на messages и
  подходящие режим/разрешения приложения. Подписок и отправки сервер не выполняет.

## Переход на Unified Login

- main.py читает назначенный аккаунт и одну страницу диалогов со вложенными
  сообщениями. Размеры страниц, предупреждения и обычный запуск сохранены.
- Общий HTTP-код вынесен из main.py в api.py: graph.facebook.com, общая
  META_API_VERSION, Bearer, закрытие ресурсов, тайм-аут и безопасные ошибки.
- auth.py использует Meta app ID/secret, META_CONFIG_ID и REDIRECT_URI.
  При входе проверяются state и адрес редиректа. Код сразу обменивается на
  бизнес-токен, сохраняемый как META_ACCESS_TOKEN. to_long_lived удалён.
- refresh получает client_business_id и вызывает API управления бизнес-токенами
  с appsecret_proof. Для операции нужен business_management. Сохранение нового
  токена остаётся явным через save_token; автоматического обновления нет.
- publisher.py сохраняет фото, Reels, Stories и карусели; использует ID аккаунта
  вместо /me. ID берётся из INSTAGRAM_ACCOUNT_ID или именованного account_id.
  Карусели поддерживают до 20 элементов; обработка видео ожидается с тайм-аутом.
- Старые Instagram URL, scopes и grant types удалены. .env и личные данные
  не менялись. Зависимости, lock-файл и logging_config.py не менялись.

## Проверки

До упрощения рабочая схема была подтверждена реальными GET: назначенный аккаунт,
пять диалогов и 35 сообщений. Это результат предыдущей версии.
После перезагрузки окна: весь набор — 50 passed; Ruff lint и форматирование
успешны. Сеть и загрузка настоящего .env в тестах заблокированы, сохранение
токенов проверяется во временных файлах. Живые запросы не выполнялись.
Первый запуск pytest: 45 passed, три ошибки доступа к системной временной папке.
Повтор с уникальной временной папкой внутри проекта прошёл; папка удалена.
mise.exe в среде агента не запускается, проверки выполнены Python существующего
uv-окружения без установки пакетов.

## Ограничения

Одна страница: запрашиваются пять диалогов и по 20 сообщений. При наличии
продолжения выводится предупреждение. Полная история и отправка не проверены,
вебхуки проверены только изолированно. Срок действия токена неизвестен. Получение/обновление
токена и все типы публикации проверены на HTTP-моках, не на реальном аккаунте.
Для входа из Python нужно заполнить META_CONFIG_ID, Meta APP_ID/APP_SECRET и
согласовать REDIRECT_URI с Meta. Для публикаций нужны instagram_basic и
instagram_content_publish; доступность этих прав у текущего токена не проверена.
Следующий шаг — отдельно разрешённая проверка нужной операции на аккаунте.
